# レコメンデーションキーに基づくレコメンデーションの設定 {#base-on-recommendation-key}

>[!BEGINSHADEBOX]

**このページでは、** [!DNL Adobe Target Recommendations]のアクティビティでレコメンデーションのベースに使用できるアルゴリズムの種類、アルゴリズム、レコメンデーションキーについて説明します。

>[!ENDSHADEBOX]

アルゴリズムベースのレコメンデーションでは、訪問者の行動のコンテキストを使用して、[!DNL Adobe Target] [!DNL Recommendations]件のアクティビティで関連する結果を表示します。 各アルゴリズムタイプは、独自のアルゴリズムセットを提供します。 アルゴリズムの種類とそのアルゴリズムの概要については、[条件の概要](/help/main/c-recommendations/c-algorithms/algorithms.md#section_885B3BB1B43048A88A8926F6B76FC482)を参照してください。

各条件は独自のタブで定義されます。 トラフィックは条件テストで均等に分割されます。2つの条件を使用すると、トラフィックはそれらの間で均等に分割され、2つの条件と2つのデザインを使用すると、トラフィックは4つの組み合わせの間で均等に分割されます。 また、サイト訪問者の割合を設定して、デフォルトのコンテンツを表示することもできます。 その場合、指定された割合の訪問者にデフォルトのコンテンツが表示され、残りは基準とデザインの組み合わせに分割されます。

条件の作成とそのアルゴリズムのタイプとアルゴリズムの定義について詳しくは、[条件の作成](/help/main/c-recommendations/c-algorithms/create-new-algorithm.md)を参照してください。

アルゴリズムは、ページのタイプに応じて異なります。 以下の節では、各アルゴリズムタイプとそのアルゴリズムについて説明します。

## カートベース {#cart-based}

**[!UICONTROL カートベース]**&#x200B;のアルゴリズムタイプでは、訪問者の現在のカートの内容に基づいてアイテムがレコメンドされます。 レコメンデーションキーは、[mbox パラメーター`cartIds`](https://experienceleague.adobe.com/docs/target-dev/developer/recommendations.html?lang=ja){target=_blank}でコンマ区切りの値として指定されます。 最初の 10 個の値のみが考慮されます。

カートベースのレコメンデーションロジックは、ユーザーベースのアルゴリズム「**[!UICONTROL おすすめ]**」と、アイテムベースのアルゴリズム「**[!UICONTROL これを閲覧した人、購入した人]**」および「**[!UICONTROL これを購入した人、購入した人]**」に似ています。

[!DNL Target]は、共同フィルタリング技術を使用して、訪問者のカート内の各項目の類似点を特定し、すべての項目の行動上の類似点を結合リストに結合します。

マーケターは、[!DNL Target]が1つのセッション内または複数のセッション間で訪問者の行動を確認するかどうかを選択できます。

* **[!UICONTROL 単一セッション]**：他の訪問者が1回のセッション内に行った内容に基づきます。

  1つのセッションは、使用状況、機会、イベントに基づいて互いに「一致」する製品に適しています。 例えば、プリンターを購入する訪問者にはインクと紙も、ピーナッツバターを購入する訪問者にはパンとゼリーも必要です。

* **[!UICONTROL セッション全体]**：複数のセッションで他の訪問者が行った処理に基づきます。

  複数のセッションは、訪問者の好みや好みに基づいて、互いに強く「合う」製品に適しています。 例えば、「スター・ウォーズ」が好きな訪問者は、必ずしも両方の映画を同じ席で見たいわけではないとしても、インディアナ・ジョーンズが好きかもしれません。 同様に、ボードゲーム「コードネーム」が好きな訪問者は、両方のゲームを同時にプレイできない場合でも、ボードゲーム「アバロン」が好きかもしれません。

[!DNL Target]は、訪問者の行動が1つのセッション内で考慮されるか、複数のセッション間で考慮されるかに関係なく、現在のカート内のアイテムに基づいて、各訪問者に対するレコメンデーションを行います。

| --- | --- | --- | --- |

### [!UICONTROL &#x200B; サイト全体で最も閲覧された] スコアリング {#most-viewed}

推奨事項は、最も頻繁に閲覧された項目で、最新性/頻度の基準によって次のように決定されます。

* 初回の商品閲覧は 10 ポイント
* 以降の閲覧は毎回 5 ポイント
* セッションの最後に、すべての値を2で割ります

例えば、サーフボード A、サーフボード Bを1つのセッションで表示すると、A: 10、B: 5になります。 セッションが終了すると、結果はA:5、B:2.5になります。 同じ項目が次のセッションで表示される場合、値はA:15、B:7.5に変更されます。

### [!UICONTROL &#x200B; カテゴリー別に最も閲覧された] スコアリング {#most-viewed-category}

レコメンデーションは、最も多くのアクティビティを受け取ったカテゴリです。 「最も閲覧されたアイテム」と同じ方法を使用しますが、カテゴリは製品ではなくスコアリングされ、最新性/頻度の基準は次のとおりです。

* 初回のカテゴリ閲覧は 10 ポイント
* 以降の閲覧は毎回 5 ポイント

訪問ごとに、以前に閲覧された非現在のカテゴリのスコアが1減少します。

例えば、1つのセッションでカテゴリ A、カテゴリ Bを表示すると、A: 9、B: 10になります。 同じ項目が次のセッションで表示される場合、値はA:20、B:9に変更されます。

### プロファイル属性アルゴリズム {#profile-attribute-algorithms}

>[!CONTEXTUALHELP]
>id="target_recommendations_profile_attribute"
>title="プロファイル属性"
>abstract="プロファイルスクリプトを使用してプロファイル属性を作成できます。 プロファイルスクリプトを作成してアクティブ化すると、対応するプロファイル属性をこのアルゴリズムで使用できます。"

プロファイル属性&#x200B;**によって最も閲覧されたユーザー**&#x200B;[!UICONTROL &#x200B;とプロファイル属性&#x200B;]&#x200B;**によって上位の販売者**&#x200B;は、属性を入力するプロファイル スクリプトに依存しています。 スクリプト名は`recsAttribute`接頭辞で始める必要があります。したがって、[!DNL Target]は`user.recsAttribute<Name>`として保存します。 ユースケースに関連する訪問者の特徴に合わせてスクリプトを作成できます。 プロファイルスクリプトを使用したプロファイル属性の設定について詳しくは、[&#x200B; プロファイルパラメーター](https://experienceleague.adobe.com/ja/docs/target/using/audiences/visitor-profiles/profile-parameters)を参照してください。

例えば、次の`recsAttributeRegion`という名前のスクリプトは、訪問者の地域に関する推奨事項をベースにしています。

```
var region = mbox.param('userRegion');
if (region) return region;
```

同様に、`recsAttributeLoyaltyTier`という名前の次のスクリプトは、訪問者のロイヤルティ層に関する推奨事項をベースにしています。

```
var tier = mbox.param('visitorLoyaltyTier');
if (tier) return tier;
```

スクリプトを作成してアクティブ化すると、対応する&#x200B;**[!UICONTROL 地域]**&#x200B;または&#x200B;**[!UICONTROL ロイヤルティ層]** エントリが、条件を作成ウィンドウのプロファイル属性ドロップダウンで使用できるようになります。 `recsAttribute` プレフィックス自体はドロップダウンに表示されません。

### [!UICONTROL 最近閲覧した項目]の詳細 {#recently-viewed}

**[!UICONTROL 最近閲覧した項目]** アルゴリズムは、特定の[環境](/help/main/administrating-target/hosts.md)に固有の結果を返します。 別々の環境に属する 2 つのサイトがあり、訪問者がそれらのサイト間を移動した場合、各サイトでは、そのサイトで最近表示された項目のみが表示されます。 2つのサイトが同じ環境にあり、訪問者が2つのサイトを切り替えると、訪問者は両方のサイトで同じ最近表示された項目を見ることができます。

**[!UICONTROL 最近閲覧した項目]**&#x200B;の条件は、バックアップの推奨事項には使用できません。

**[!UICONTROL 最近閲覧した項目]**&#x200B;または&#x200B;**[!UICONTROL 最近閲覧したメディア]**&#x200B;をフィルタリングして、特定の属性を持つ項目のみを表示できます。

* **[!UICONTROL 最近表示した]**&#x200B;条件は、レコメンデーションの他の条件と同様に設定可能です。
* [&#x200B; コレクション &#x200B;](/help/main/c-recommendations/c-products/collections.md)、[除外事項](/help/main/c-recommendations/c-products/exclusions.md)、[除外事項](/help/main/c-recommendations/c-algorithms/use-dynamic-and-static-inclusion-rules.md) （価格と在庫に関する特別なルールを含む）は、他の条件と同じように使用できます。

ひとつのユースケースは、複数の企業を擁する多国籍企業で、訪問者は複数のデジタルプロパティにまたがる商品を閲覧する場合があります。 最近閲覧したアイテムは、閲覧したプロパティに制限できるため、別のプロパティのサイトには表示されません。

>[!NOTE]
>
>**[!UICONTROL 最近閲覧した項目]**&#x200B;は、アクティビティのグローバル除外の設定と選択したコレクションの設定の両方を尊重します。 アイテムがグローバル除外によって除外されるか、選択したコレクションに含まれていない場合、アイテムは表示されません。 したがって、**[!UICONTROL 最近閲覧した項目]**&#x200B;の条件を使用する場合は、通常、「すべてのコレクション」設定を使用する必要があります。

## カスタム条件 {#custom}

**[!UICONTROL カスタム条件]** アルゴリズムタイプは、アップロードされたカスタムファイルに基づいてアイテムをレコメンドします。

推奨事項は、ユーザー&#x200B;*x*&#x200B;またはプロファイル *x*&#x200B;の属性を使用して、訪問者のプロファイルに保存されている項目によって決定されます。 このオプションを選択した場合、`entity.id` の値がプロファイル属性に存在する必要があります。 レコメンデーションがカスタム属性に基づいている場合、最初にカスタム属性を選択し、次にレコメンデーションタイプを選択する必要があります。

カスタム基準の出力にリアルタイムフィルタリングを適用できます。 例えば、推奨される項目は、訪問者のお気に入りのカテゴリまたはブランドの項目に限定できます。 これにより、オフラインの計算とリアルタイムのフィルタリングが組み合わされるため、[!DNL Target]はオフラインの計算レコメンデーションまたはカスタム監修リストにパーソナライゼーションを追加できます。 さらに、データサイエンスと調査結果を、Adobe Adobeの配信、実行時フィルタリング、A/B テスト、ターゲティング、レポート、統合と組み合わせて活用できます。

**[!UICONTROL カスタム条件]**&#x200B;の包含ルールは、訪問者の興味に基づいて、静的なレコメンデーションを動的なレコメンデーションに変換します。

* カスタム条件は、レコメンデーションの他の条件と同じように変更可能です。
* [&#x200B; コレクション &#x200B;](/help/main/c-recommendations/c-products/collections.md)、[除外事項](/help/main/c-recommendations/c-products/exclusions.md)、[除外事項](/help/main/c-recommendations/c-algorithms/use-dynamic-and-static-inclusion-rules.md) （価格と在庫に関する特別なルールを含む）は、他の条件と同じように使用できます。

考えられるユースケースは次のとおりです。

* カスタムキュレーションされたリストから映画をレコメンドしますが、訪問者がまだ映画を視聴していない場合に限ります。
* オフラインアルゴリズムを実行し、その結果にもとづいてレコメンデーションを実施することで、在庫切れの商品をレコメンデーションしないようにします。
* この訪問者のお気に入りのカテゴリのアイテムのみを含めます。

### カスタムレコメンデーションキー

レコメンデーションは、カスタムプロファイル属性の値に基づいて行うことができます。 例えば、訪問者が最後にキューに追加したムービーに基づいて、推奨ムービーを表示できます。

1. 「**[!UICONTROL Recommendation Key]**」ドロップダウンリストからカスタムプロファイル属性を選択します（例：「**[!UICONTROL Last Show Added to Watchlist]**」）。

1. **[!UICONTROL レコメンデーションロジック]**&#x200B;を選択します（例：「**[!UICONTROL これを表示したユーザー、その]**」を表示したユーザー）。

カスタムプロファイル属性が単一のエンティティ IDに直接一致しない場合は、[!DNL Recommendations]がエンティティにどのように一致するかを指定します。 例えば、訪問者のお気に入りブランドのトップセラー商品を表示するには、次の手順を実行します。

1. **[!UICONTROL Recommendation Key]** ドロップダウンリストからカスタムプロファイル属性を選択します（例：「お気に入りブランド」）。

1. このキーで使用する&#x200B;**[!UICONTROL レコメンデーションロジック]**&#x200B;を選択します（例：「**[!UICONTROL トップセラー]**」）。

   「**[!UICONTROL 一意の値でグループ化]**」オプションが表示されます。

1. 選択したキーに一致するエンティティ属性を選択します。 この場合、「**[!UICONTROL お気に入りブランド]**」は`entity.brand`と一致します。

   [!DNL Recommendations]は、ブランドごとに「**[!UICONTROL トップセラー]**」リストを生成し、訪問者の&#x200B;**[!UICONTROL お気に入りのブランド]** プロファイル属性に保存されている値に基づいて、訪問者に適切な「**[!UICONTROL トップセラー]**」リストを表示するようになりました。

### [!UICONTROL &#x200B; サイトの親和性] {#site-affinity}

品目間の関係の確実性に基づいて品目をレコメンドします。 この条件は、**[!UICONTROL 包含ルール]** スライダーを使用して、レコメンデーションを表示する前にどの程度のデータが必要かを設定するように設定できます。 例えば、「非常に強い」を選択した場合、一致の確実性が最も高い製品が推奨されます。

例えば、非常に強い親和性が設定され、設計に5つの項目が含まれ、そのうちの3つが接続しきい値の強度を満たす場合、最小強度の要件を満たさない2つの項目は推奨事項に表示されず、定義されたバックアップ項目に置き換えられます。 最も強い親和性を持つ品目が最初に表示されます。

別の例として、オンラインretailerでは、その後の訪問者の訪問時に、以前のセッションで関心が示された項目をレコメンドできます。 各訪問者のセッションのアクティビティをキャプチャし、最新性と頻度モデルにもとづいて親和性を計算します。 訪問者がサイトに戻ってくると、サイト親和性データを使用して、サイトでの過去のアクションに基づいたレコメンデーションが表示されます。

弱いサイト親和性は、多様な商品コレクションや多様なサイト行動を持つ顧客に最適な結果をもたらす可能性があります。

このロジックは、次のレコメンデーションキーで使用できます：**[!UICONTROL 現在のアイテム]**、**[!UICONTROL 最後に購入したアイテム]**、**[!UICONTROL 最後に閲覧したアイテム]**、**[!UICONTROL 最も閲覧されたアイテム]**。
