# 以前のリリースのリリースノート

[!DNL Target Standard/Premium]、[!DNL Target] プラットフォームおよび [!DNL Target] JavaScript ライブラリ（at.js）のリリースノートなど、以前の [!DNL Adobe Target] リリースのリリースノートです。

リリースノートは、リリースの月と年ごとに降順で表示されます。

>[!NOTE]
>
>今月の Target リリース（プラットフォームおよび Target Standard/Premium）について詳しくは、[Target のリリースノート（最新）](/help/main/r-release-notes/release-notes.md#reference_8FE40B43A5A34DDF8F26A53D55EE036A) を参照してください。

## リリースノート - 2025年

### [!DNL Target Standard/Premium] 25.11.2 （2025年11月14日）

**決定オファー**

+++詳細を見る

* **更新されたUIで非表示または無効なセレクターを使用して決定を提供できません。** 更新されたUIで、要素がVisual Experience Composer （VEC）に表示されない限り、非表示または無効なセレクターに関連付けられたオファーの決定を編集できない問題を解決しました。 編集はパネルから直接サポートされるようになりました。従来のUIで使用できる機能を復元し、セレクターの表示に関係なくオファーの決定を変更できるようになりました。 （TGT-53899）

+++

**レコメンデーション**

+++詳細を見る

* **アクティビティの条件を編集すると、ページがクラッシュしました。** 更新されたUIで、アクティビティ条件を編集するとページがクラッシュし、`useCrudActionsCtx`に関連するコンソールエラーが発生する問題を解決しました。 条件エディターが正しく読み込まれ、機能するようになり、アクティビティを中断することなく編集できるようになりました。 （TGT-53971）
* **[!UICONTROL メッセージ &#x200B;]列が、更新されたUIに製品データを断続的に表示できませんでした。** 更新された[!UICONTROL Recommendations] UIで、[!UICONTROL &#x200B; カタログ検索]の[!UICONTROL &#x200B; メッセージ &#x200B;]列が、フィードに値が存在していたにもかかわらず、製品データの表示に断続的に失敗する問題を解決しました。 列は、すべての製品で正しいメッセージ値を一貫して表示するようになり、列の再設定を手動で必要とせずに信頼性の高い可視性を確保します。 （TGT-52777）
* 更新されたUIにアクティビティを保存すると、**[!UICONTROL おすすめのデータのダウンロード &#x200B;] ボタンが表示されません。** 更新されたUIで、再保存後でも、特定の保存済みアクティビティに対して「[!UICONTROL おすすめデータをダウンロード &#x200B;]」ボタンが表示されない問題を解決しました。 このボタンは、あらゆるアクティビティで一貫して表示されるようになったため、ユーザーは回避策を必要とせずにレコメンデーションデータを確実に書き出すことができます。 （TGT-53802）
* **コレクションから特定の製品を開くと、「リクエストされたリソースが見つかりませんでした」と返され、モーダルには閉じるオプションがありませんでした。** 更新されたRecommendations UIで、コレクションから特定の製品を開くと、「リクエストされたリソースが見つかりませんでした」エラーがトリガーされ、閉じるオプションなしで空白モーダルが表示される問題を解決しました。 モーダルで製品の詳細が正しく読み込まれるようになり、クローズオプションが常に使用できるようになりました。 （TGT-53986）

### データストリームの更新（2025年9月19日（PT））

データストリーム IDとサンドボックスの組み合わせは、[!DNL Adobe Target]宛先接続で一意である必要があります。

データストリーム IDとサンドボックス名の組み合わせがIMS組織内で一意である必要があることを強制するために、[!DNL Target]宛先接続の検証ロジックを更新しました。つまり次の式になります。

* 同じデータストリーム ID + サンドボックス名のペアを複数の[!DNL Target]宛先接続で再利用することはできません。
* 同じデータストリーム IDを異なる接続に使用できるのは、異なるサンドボックスで設定されている場合のみです。
* このルールは、「なし」が選択されている場合を含め、すべてのデータストリーム選択に適用されます。

このアップデートにより、設定の一貫性が確保され、マルチサンドボックス環境での競合を防ぐことができます。 詳しくは、*Adobe Target Destinations* ガイドの[Experience Platform connection](https://experienceleague.adobe.com/en/docs/experience-platform/destinations/catalog/personalization/adobe-target-connection){target=_blank}を参照してください。
