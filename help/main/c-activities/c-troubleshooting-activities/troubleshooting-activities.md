# トラブルシューティングの基本を学ぶ {#troubleshooting-activities}

>[!BEGINSHADEBOX]

**このページ：** [!DNL Adobe Target] アクティビティがサイトに表示されないか、期待どおりに動作しない場合の一般的な問題の解決策を検索します。

>[!ENDSHADEBOX]

サイトに[!DNL Adobe Target] アクティビティが表示されない原因はいくつかあります。 次の問題と提案された解決策を使用して、原因を特定し、修正を適用します。

>[!NOTE]
>
>次のトラブルシューティング情報に加えて、[!DNL Adobe Target]のトラブルシューティングアクティビティやその他の機能に関する追加のトラブルシューティングトピック、FAQ、その他の有用な情報へのリンクについては、[Target](/help/main/r-troubleshooting-target/troubleshooting-target.md)のトラブルシューティングを参照してください。

## アクティビティが期待どおりに表示されない {#not-displayed}

+++ デフォルトコンテンツが表示されています

アクティビティが完了し、アクティブ化されていることを確認します。

+++

</br>

+++ アクティビティは公開されていません

**検証：** **[!UICONTROL 概要]** タブで、アクティビティが非アクティブとドラフトのどちらに設定されているかを確認します。

**オプション：**

* アクティビティをアクティブ化します。
* プレビューリンクを使用して、非アクティブなアクティビティを表示します。

+++

</br>

+++ オーディエンスターゲティング条件の対象にはなりません

**検証：** **[!UICONTROL 概要]** ページでターゲティング条件を確認します。

**オプション：**

* オーディエンスの対象を絞り込んでから、もう一度試してください。
* プレビューリンクを使用して、ターゲティング条件を回避します。

+++

</br>

+++ このページはページターゲティング条件に適格ではありません

**検証：** **[!UICONTROL 概要]** ページで、ページがターゲティング条件の範囲外にあるかどうかを判断します。

**オプション：**

* **[!UICONTROL Visual Experience Composer]**&#x200B;に移動し、URL/詳細/現在のページをクリックします。

+++

</br>

+++ 新しいエクスペリエンスではなく、以前のエクスペリエンスが表示される

**検証：**&#x200B;次のいずれかのオプションを試してから、もう一度エクスペリエンスを表示してください。

**オプション：**

* キャッシュとCookieをクリアしてから、もう一度試してください。
* 別のブラウザーを使用してみます。
* プライベートモードまたはシークレットモードを使用します。

+++

</br>

+++ アクティビティの設定後、ページの構造が変更されました

**検証：**&#x200B;既存のアクティビティの&#x200B;**[!UICONTROL Visual Experience Composer]**&#x200B;に移動し、セレクター（または構造）が変更されたことを示す警告メッセージを探します。

**オプション：**

* アクティビティを再構築します。

ページの変更が[!DNL Target]のコンテンツ表示機能にどのような影響を与えるかについて詳しくは、[&#x200B; ページの変更シナリオ &#x200B;](/help/main/c-experiences/c-visual-experience-composer/r-troubleshoot-composer/vec-scenarios.md)を参照してください。

+++

</br>

+++ ページの構造は、ページ読み込み中（実行時）に変更されます

**検証：**&#x200B;開発者に確認してください。

**注意：** [!DNL Target]がアクティビティの変更を適用する場所を認識するには、同じクラスの要素を動的に挿入したり、兄弟のクラスを動的に変更したりしないでください。

**オプション：**

* IDを使用して、テストされる各要素を一意に識別するようにページコードを更新します。
* 前述のように、クラスまたは兄弟を動的に変更するのをやめます。

ページの変更が[!DNL Target]のコンテンツ表示機能にどのような影響を与えるかについて詳しくは、[&#x200B; ページの変更シナリオ &#x200B;](/help/main/c-experiences/c-visual-experience-composer/r-troubleshoot-composer/vec-scenarios.md)を参照してください。

+++

</br>

+++ 他のアクティビティが同じページで実行されています

**検証：** 「**[!UICONTROL 衝突]**」タブを使用して、他のアクティビティが実行されているかどうかを確認します。

**メモ：** 「**[!UICONTROL コリジョン]**」タブは、テンプレートテストモジュールでは機能しません。

**オプション：**

* このアクティビティの優先度を高くします。
* 他の活動の優先度を下げる。
* 他のアクティビティを非アクティブ化します。

+++

## ユーザー、API、UI {#users-api-ui}

+++ [!DNL Target] UIを使用してアクティビティを作成しましたが、API経由で更新できません

[!DNL Target] UIを使用して作成されたアクティビティは、[!DNL Target] UIを使用して更新する必要があります。 API を使用して作成されたアクティビティは、API から更新する必要があります。 例えば、APIを使用してアクティビティを作成し、後で[!DNL Target] UIを使用してアクティビティを編集した場合、すべての変更が更新されるわけではありません。 すべての変更はバックエンドに保存され、別のAPI呼び出しを行うことで更新できます。

ベストプラクティスとして、アクティビティの作成に使用したのと同じメソッド（UIまたはAPI）を使用して、アクティビティを更新します。

+++

</br>

+++ 最近[!DNL Target]に追加されましたが、アクティビティを作成できません

**検証：** 「**[!UICONTROL アクティビティを作成]**」をクリックします。 オプションが有効でない場合、たいていは、アクティビティを作成するのに十分な権限がありません。

**オプション：**

[!DNL Target]でユーザーとして追加された後、アクティビティを作成するには&#x200B;**[!UICONTROL 承認者]**&#x200B;の役割が必要です。

* アカウントの管理者に承認者を依頼します。
* 管理者である場合は、[!DNL Target]の&#x200B;**[!UICONTROL 管理]** > **[!UICONTROL ユーザー]**&#x200B;の&#x200B;**[!UICONTROL 承認者]**&#x200B;の役割を自分に与えます。 [承認者の役割を自分に割り当てる](/help/main/administrating-target/start-target.md#task_15CAA437A71444E2932B333D5E66A3C7)を参照してください。

+++

</br>

+++ [!DNL Target] APIを使用してアクティビティをアクティブ化しましたが、アクティビティは[!DNL Target] UIで[!UICONTROL 非アクティブ &#x200B;]のステータスを示します

[!DNL Target] APIを使用してUI外でアクティビティをアクティブ化するなど、特定のアクションを実行する場合、更新がUIに反映されるまでに最大10分かかる場合があります。

+++

</br>

+++ プロファイルスクリプトを削除すると、エラーメッセージが表示される

**検証：** [!DNL Target]からプロファイルスクリプトを削除すると、「プロファイルスクリプトを削除できませんでした」というエラーメッセージが表示されます。

**オプション：**

次のいずれかを実行します。

* プロファイルスクリプトをもう一度削除します。 成功メッセージが表示されます。
* [!DNL Target] インポーターが実行されるまで約10分待ちます。 インポーターがプロファイルスクリプトのリストを更新します。

+++

## コールとコンバージョン {#calls-and-conversion}

+++ 一部のajax [!DNL Target]呼び出しが機能しません

**注意：**&#x200B;同じ名前で複数のajax [!DNL Target]呼び出しが行われますが、同じページで異なるパラメーターが機能しません。 最初の呼び出しのみが行われます。

+++

</br>

+++ アクティビティのコンバージョン後、訪問者はいかなるエクスペリエンスにも属しません

まれに、エクスペリエンスに対して訪問者を認定するアクティビティのコンバージョン指標が、アクティビティの認定と同じリクエストで送信された場合、訪問者はリクエストの送信後にエクスペリエンスに存在しない可能性があります。 この状況では、訪問者にはデフォルトのコンテンツが表示され、トークンを介してキャプチャされたエクスペリエンス IDは–1になります。 [!DNL Adobe]は、同じ[!DNL Target] リクエストでアクティビティの選定とコンバージョンを送信することはお勧めしません。

同じリクエストで両方の指標を送信する場合は、**[!UICONTROL 詳細設定]**&#x200B;を使用して、変換後も訪問者が同じエクスペリエンスに留まるように指定できます。

+++
