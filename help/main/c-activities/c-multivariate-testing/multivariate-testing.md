# [!UICONTROL 多変量テスト &#x200B;]を開始する {#get-started-mvt}

>[!BEGINSHADEBOX]

**このページ：**&#x200B;では、[!DNL Target]が使用する&#x200B;**[!UICONTROL 多変量テスト]**&#x200B;の仕組み、A/B テストの代わりにそれを使用するタイミング、部分的な要因テストがトラフィック要件をどのように削減するかを説明します。

>[!ENDSHADEBOX]

[!DNL Adobe Target]の&#x200B;**[!UICONTROL 多変量テスト]** （MVT）アクティビティは、ページ上の要素のオファーの組み合わせを比較し、特定のオーディエンスに対してどの組み合わせが最も効果的かを判断します。 また、アクティビティの成功に最も影響を与える要素を特定するのにも役立ちます。 多変量テストは、ページ上の他の要素と比較して、特定の要素がコンバージョンに与える相対的な影響を特定し、効果的であることが示された要素の組み合わせを改善するのに役立ちます。

**[!UICONTROL 多変量テスト]**&#x200B;は、A/B テストと比較して2つの利点があります。

* ページ上のどの要素がコンバージョンに最も大きな影響を与えるかを示します。これは「メイン効果」とも呼ばれます。 この情報は、例えば、最も注目を集めるコンテンツをどこに配置するかを決定するのに役立ちます。
* これは、ページ上の2つ以上の要素の間の複合効果を見つけるのに役立ちます。これは「インタラクションエフェクト」とも呼ばれます。 例えば、特定の広告は、特定のバナーやメイン画像と組み合わせると、より多くのコンバージョンを生み出す場合があります。

[!DNL Target] では、コンテンツの最適化に役立つように、全因子多変量分析テストが使用されます。 完全実施要因による多変量分析テストでは、同じ確率でコンテンツのあらゆる可能な組み合わせを調べます。 例えば、それぞれ 3 つのオファーが組み込まれたページ要素が 2 つある場合は、9 つの組み合わせ（3 x 3）になります。 3 つの要素があり、そのうちの 2 つの要素に 3 つのオファーが、1 つの要素に 2 つのオファーが組み込まれている場合は、組み合わせは 18（3 x 3 x 2）になります。

[!DNL Target]では、それぞれの組み合わせが1つのエクスペリエンスです。 **[!UICONTROL 多変量テスト]**&#x200B;では、それぞれのエクスペリエンスを比較して、どの組み合わせが最も効果的かを確認できます。 同時に、[!DNL Target]はデータを収集および分析して、各場所とオファーが成功指標にどのように影響しているかを把握します。

![多変量テストの組み合わせ](assets/multivariate.png)

生成できる組み合わせの数が多いため、**[!UICONTROL 多変量テスト]**&#x200B;では、A/B テストよりも多くの時間とトラフィックが必要です。 各エクスペリエンスに対して統計的に有意な結果を得るためには、ページに十分なトラフィックが必要です。 有益な結果を得るには、ページが受信するトラフィック量を把握し、適切な時間に最適な組み合わせ数をテストします。

[Traffic Estimator](/help/main/c-activities/c-multivariate-testing/t-create-multivariate-test/traffic-estimator.md#traffic-estimator)は、トラフィックに合ったテストを設計するのに役立ちます。 インプレッション数やコンバージョン数を把握し、1日あたりのトラフィックレベルを考慮する必要があります。 アクティビティに含まれるエクスペリエンスが多ければ多いほど、アクティビティに含めるトラフィックが増えるか、実行する時間が長くなります。 トラフィック量が多くない場合は、いくつかの組み合わせをテストします。 そうでなければ、有意義な試験結果を生成するために必要な時間が長すぎて有用ではない可能性があります。

## MVTの用語 {#mvt-terminology}

いくつかの用語が、業界のさまざまな方法で使用されています。 次の表は、多変量テストの設定時に[!DNL Target]が使用する用語を定義しています。

| 用語 | 定義 |
|--- |--- |
| 組み合わせ | 複数の場所で複数のコンテンツオプションをテストする場合に作成するコンテンツのバリエーション。 例えば、3つのコンテンツオプションを持つ3つの場所をテストする場合、27の可能な組み合わせ（3x3x3）があります。 サイト訪問者には、ひとつの組み合わせが表示されます。これはエクスペリエンスとも呼ばれます。 |
| コンテンツ | 場所内のテストのバリエーションを構成するテキストまたは画像。 多変量分析テストでは、複数の場所にあるいくつかのコンテンツオプションを比較します。 MVT 手法では、コンテンツは「*レベル*」と呼ばれる場合があります。 |
| 要素 | MVT テストでテストされるコンテンツバリエーションを含むDOM要素。 *場所*&#x200B;も参照してください。 |
| 場所 | ページ上の特定のコンテンツ領域。多くの場合、単一の DOM 要素に含まれています。 MVT の方法論においては、場所は「*因子*」と呼ばれることもあります。 全因子多変量分析テストでは、場所におけるすべての可能なオファーの組み合わせが比較されます。 |

## [!UICONTROL 多変量テスト &#x200B;]とA/Bの使用例 {#when-to-use-mvt}

次の表は、**[!UICONTROL 多変量テスト]**、A/B テスト、またはその両方を同時に使用してページを最適化するタイミングを示しています。

| 状況 | 今後の施策 | 詳細 |
|--- |--- |--- |
| テストする要素は3つ未満です。 | 一連のA/B テストの実施： | MVT テストは、テストする要素が 3 つ以上ある場合に使用します。 |
| ページのレイアウトとコンテンツの両方を最適化できます。 | ページレイアウトを最適化するにはA/B テストを実施し、その後、MVT テストを実施して、ページの各要素で最適なコンテンツを特定します。 | A/B テストは、レイアウトに関する重要なフィードバックを提供でき、MVT テストは、ページデザインの要素内のコンテンツをテストするのに優れています。 複数のコンテンツオプションをテストする前に、レイアウトでA/B テストを実行することで、最適なレイアウトと最も効果的なコンテンツを決定できます。 |
| 異なるエクスペリエンスの数が5を超え、2つ以上の要素にまたがる。 | MVT テストを使用してどの要素が最も重要かを判断し、その後その要素に絞って A/B テストを実行します。 | MVT テストによって、コンバージョンが向上する可能性が最も高そうなページ領域を判定できます。 マーケティング担当者は、これらの要素に重点を置いてテストをおこなうことができます。 例えば、MVT テストによって、目標を達成するための最も重要な要素がコールトゥアクションであることがわかります。 その後、A/B テストを実行して、2つの特定の画像を比較したり、call to actionの表現や色を比較したりするなど、結果をさらに絞り込むことができます。 1つ以上のA/B テストを使用してMVT テストを実行することで、必要な結果に最適なコンテンツを決定できます。 |

含める要素の数やテストの計画方法など、その他の考慮事項については、[多変量テストのベストプラクティス &#x200B;](/help/main/c-activities/c-multivariate-testing/best-practices.md)を参照してください。

## 部分的階乗テスト {#partial-factorial}

[!DNL Target] では、全因子多変量分析テストがビルトインアクティビティオプションとして用意されています。 統計では、「実験の設計」は、どの要因が結果に影響を与えるかを決定するために、多くのアプローチ、または設計を提供します。 そのようなアプローチの1つが、部分的要因テスト用の[Taguchi Method](https://en.wikipedia.org/wiki/Taguchi_methods)です。 田口手法では、マーケターがテストする必要のあるエクスペリエンスの順列数を減らし、多変量テストのトラフィック要件を減らす一連の仮定を作成できるようにします。 このアプローチは、[&#x200B; オフラインスプレッドシート &#x200B;](/help/main/assets/MVT-Taguchi-Partial-Factorial-Design-02102017.xlsx)を使用して[!DNL Target]に適用できます。

チームが他の実験デザインのアプローチを使用している場合は、スプレッドシートをカスタム実験デザインの参照実装として使用できます。

オフライン計算スプレッドシートを使用する際は、次のヒントを考慮してください。

* 変更するエレメントと、各エレメントのバージョン数（3x2、4x3など）を選択します。
* 番号付けの方法には一貫性を持たせます。 例えば、ボタンが要素 1 で、オプションが青、緑、黄の場合、青色のボタンを 1-1、緑色のボタンを 1-2、黄色のボタンを 1-3 とします。
* オフラインスプレッドシートには、必要になるエクスペリエンスの数が示されています（例えば、3x2 の場合は 4 つ、4x3 の場合は 9 つ）。
* [Visual Experience Composer（VEC）](/help/main/c-experiences/experiences.md)を使用して A/B ワークフローのエクスペリエンスを構築します。 カスタムコードの使用、HTML の編集、WYSIWYG または任意の組み合わせを使用できます。
* アクティビティが終了したら（サンプルサイズ計算ツールに基づいて）、スプレッドシートを通じて結果を実行し、他の詳細を確認します。
