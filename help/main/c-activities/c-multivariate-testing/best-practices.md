# [!UICONTROL 多変量テスト &#x200B;]のベストプラクティス {#mvt-best-practices}

>[!BEGINSHADEBOX]

**このページで：**&#x200B;信頼性の高い結果を得るために、**[!UICONTROL 多変量テスト]** アクティビティを計画、作成、分析、フォローアップする方法を説明します。

>[!ENDSHADEBOX]

次のヒントは、**[!UICONTROL 多変量テスト]** （MVT）アクティビティを[!DNL Adobe Target]で作成および実行する際に発生する可能性のあるパフォーマンスの向上、問題の回避、既知の問題の修正に役立ちます。

## 計画 {#plan}

* **テストで少なくとも3つの要素を使用してください。**

  3 つ未満の場合は、一連の A/B テストを実行します。 詳しくは、[多変量テストとA/B テストを使用する場合](/help/main/c-activities/c-multivariate-testing/multivariate-testing.md#when-to-use-mvt)を参照してください。

* **インプレッション数やコンバージョン数など、通常のトラフィック量に注意してください。**

  MVTでは、有用な結果を生成するために十分なトラフィックが必要であり、この情報は、サイトのトラフィックを超える要件を持つテストを設計する可能性を減らすのに役立ちます。

* **重要な結果を生み出す可能性の高いページ上の場所を把握します。**

  バナーやヒーロー画像は、フッターを変更するよりもコンバージョン率が高くなる可能性があります。 テストに効果の低い場所を組み込むと、ページ上のより効果の高い場所をテストするのに必要なトラフィック量や時間が増えることになります。

* **要素を互いに独立させます。**

  例えば、同じテスト内でレイアウトとコンテンツをテストしないでください。

* **テストするページのHTML コードを調べます。**

  サイトのHTML要素に重複するDOM IDがないことを確認します。 重複した ID を持っていると、同じコンテンツが複数の場所に配信されることがあります。

* **ページのバリエーションを事前に準備します。**

  各オファーのコンテンツの差異を把握し、MVT テストで使用する画像、テキストおよび HTML オファーを作成します。

* **QAの追加時間を計画します。**

  エクスペリエンスの数が増えるので、QAにはより多くの時間が必要です。

## 作成 {#create}

* **テストに必要な組み合わせより多くの組み合わせを含めないでください。**

  テストする組み合わせの数が増えると、期待に添った結果を実現するために必要なトラフィック量および時間が大幅に増加します。 例えば、それぞれ 3 つのオファーが組み込まれた場所が 3 つある場合、27 の組み合わせ（3 x 3 x 3）になります。 3 つの場所があり、そのうちの 2 つの場所に 3 つのオファーが、1 つの場所に 2 つのオファーが組み込まれている場合、組み合わせは 18（3 x 3 x 2）になります。 場所やオファーの数が増えると、組み合わせの数は大きく増加します。

* **場所とオファーに名前を付けます。**

  テスト内のそれぞれの場所およびオファーを、わかりやすい名前に変更できます。 それぞれの場所におけるオファーの数が、場所のヘッダーに表示されます。 わかりやすい名前を付けることで、レポートを検討する際にオファーを特定できます。

* **プレビュー機能を利用して、コンテンツの望ましくない組み合わせを回避します。**

  テストを開始する前に、テストによって生成されるすべてのエクスペリエンスを確認します。 矛盾するクレーム（同じエクスペリエンスで20% オフと19 ドルオフなど）や、背景や同じ色のフォントなど、互換性のないデザインとの組み合わせがないかどうかを確認します。

* **[Traffic Estimator](/help/main/c-activities/c-multivariate-testing/t-create-multivariate-test/traffic-estimator.md#traffic-estimator)を使用して、テストがページが受信するトラフィック量に合わせて設計されていることを確認します。**

  **[!UICONTROL Traffic Estimator]**&#x200B;がテスト設定に緑色の光を与えていることを確認して、必要な結果を得られるようにします。

* **各要素の代替案を互いに大きく異なるようにします。**

  必須ではありませんが、各要素に同じ数の代替案を含めることが推奨されます。

## 分析 {#analyze}

* **ロケーション貢献度レポート [を頻繁に使用して、各ロケーションとオファーのパフォーマンスを監視します。](/help/main/c-reports/multivariate-test-reports/location-contribution-report.md)**

* **エクスペリエンス パフォーマンス レポート [&#128279;](/help/main/c-reports/multivariate-test-reports/experience-performance-report.md)では、[!UICONTROL &#x200B; ベスト 5]および[!UICONTROL &#x200B; ベスト 5] フィルターを使用して表示されたデータに基づいて意思決定を行います。**

  **[!UICONTROL All]** フィルターは、目的の情報を抽出することを困難にし、すべてのエクスペリエンスをグラフに表示できるわけではありません。 最高レベルまたは最悪レベルの5以外の特定のエクスペリエンスを調べる場合は、**[!UICONTROL すべて]** フィルターを使用します。

## フォローアップ {#follow-up}

* [!DNL Target]ではライブアクティビティを編集できますが、**進行中のアクティビティを編集すると、テストがリセットされる可能性があります。** レポートで一部の変更が認識されない場合があります。 オファーライブラリでのみ、HTML オファーを安全に変更できます。

  エクスペリエンス名とレポートをリセットするアクションには、次のものが含まれます。

  * 新しい場所の追加
  * 場所の削除
  * 新しいオファーの追加、または既存の場所からのオファーの削除
  * リッチテキストオファーの編集
  * 背景色オファーの編集

* **[!DNL Analytics] ベースの指標を使用するアクティビティを編集するときにレポートスイートが読み込まれない場合（スピナーが表示されます）、**&#x200B;は指標を[!DNL Target]指標に切り替え、もう一度[!DNL Analytics] ベースの指標に切り替えます。 これで、レポートスイートがロードされるようになります。

* **1つ以上のA/B テスト**&#x200B;を使用してMVT テストを実行し、必要な結果に最適なコンテンツを決定します。 目標を達成するために最も有用な場所およびコンテンツを特定したら、A/B テストを実行して、さらに結果を絞り込むことができます。 例えば、最も重要な場所がわかっている場合は、2つの画像を比較したり、call to actionの文言や色を比較したりします。
