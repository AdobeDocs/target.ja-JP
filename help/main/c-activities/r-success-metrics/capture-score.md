# スコアキャプチャ {#capture-score}

>[!BEGINSHADEBOX]

**このページ：**&#x200B;では、キャプチャスコアエンゲージメント指標が訪問のスコアを計算する方法と、ページにスコアを割り当てる方法について説明します。

>[!ENDSHADEBOX]

[!DNL Adobe Target]のキャプチャスコアエンゲージメント指標は、訪問者がサイトで閲覧するページに割り当てられた値に基づいて集計スコアを計算します。 スコアは、訪問者が最初にアクティビティの最初の表示[!DNL Target] リクエストを最初に見た時点から開始します。

次の例は、2つのエクスペリエンス（猫の画像と犬の画像）をテストするアクティビティで、スコアがどのように計算されるかを示しています。

![猫体験訪問のページフロー、各ページのスコア ](assets/example_score.png)

この例では、最初の訪問者は猫の体験を見ます。 グローバル [!DNL Target] リクエストがページの値に基づいてページスコアで合格するとします。 マーケターが&#x200B;**任意のTarget リクエスト**&#x200B;に関連付けられた成功指標に対するページ数エンゲージメントをキャプチャした場合、訪問スコアは、cat画像の周囲で表示リクエスト後に表示されたリクエストに対して累積されます。

最初のページでは、スコアに1が加算され、2番目のページでは0.25、3番目のページでは0.10、4番目のページでは0.10が加算され、合計は1.45になります。 この合計は、通貨またはポイントのいずれかとして解釈できます。 別の訪問で、訪問者は犬の体験を見ます。 この訪問者の閲覧ページ数は少ないものの、スコアは2.10で、他の訪問者よりも価値の高いページを閲覧したため、他の訪問よりも高くなりました。

獲得コストとアフィリエイトリンクの売上高を計算に入れるには、後続のページフローに示すように、adbox とリダイレクターを渡します。 この例では、アーティクルページの両方の[!DNL Target] リクエストでスコアが渡されます。これは、既知のCPMを表している可能性があります。

![獲得コストとアフィリエイトリンクの収益がスコアとして渡されたページのフロー](assets/example_score2.png)

## ページスコアの割り当て

サイトのページに値を割り当てる場合、自分にとってそのページが持つ価値に基づいて割り当てることができます。 例えば、料理サイトでは、「体験」セクションよりも特集記事ページの方が、より多くの費用で広告を販売できます。 機能に関する記事の方が、エクスペリエンスのセクションよりも価値があります。 ページスコアを使用すると、訪問の全体的な「価値」を作成できるので、機能記事を読むユーザーは、体験を閲覧するユーザーよりも「ポイント」が多くなります。

ページにスコアを割り当てるには次の 2 つの方法があります。

* [!DNL Target] リクエストで、`mboxPageValue`という名前のパラメーターを作成します。

  例：`('global_mbox', 'mboxPageValue=10');`

  指定された値は、その[!DNL Target] リクエストを含むページが表示されるたびにスコアに追加されます。 ページ上の複数のリクエストにスコア値が含まれる場合、ページのスコアはすべてのリクエスト値の合計になります。 `mboxPageValue`は、エンゲージメントスコアを取得するために[!DNL Target] リクエストで値を渡すために使用される予約パラメーターです。 正の値も負の値も渡される可能性があります。 合計は、各訪問の最後に計算され、訪問の合計スコアが決定されます。

* ページのURLに`?mboxPageValue=n` パラメーターを渡します。

  例：`https://www.mydomain.com?mboxPageValue=5`

  指定された値は、ページ上の各[!DNL Target] リクエストのスコアに追加されます。 例えば、パラメーター`?mboxPageValue=10`を渡し、ページ上に3つの[!DNL Target] リクエストがある場合、ページのスコアは30になります。

>[!NOTE]
>
>カウンターは、エントリリクエストではなく、アクティビティの最初の表示リクエストで始まり、そのリクエストの上にある[!DNL Target]件のリクエストはスコアに含まれません。 例えば、表示リクエストがないホームページでアクティビティを入力し、表示リクエストを含むカタログページにリンクすると、カタログページに移動したときにカウンターが開始されます。

ベストプラクティスは、[!DNL Target] リクエストで値を割り当てることです。 この方法では、各リクエストの内容に応じて、測定する値を正確に把握できます。

>[!NOTE]
>
>メンテナンスを容易にするために、条件付きのJavaScript ロジックを使用して、[!DNL at.js] ファイルでサイトのページスコア値の割り当てを設定できます。 これにより、ページにコードを追加する必要がなくなります。 サポートが必要な場合は、担当のアカウントコンサルタントにお問い合わせください。

上記の 2 つの方法を組み合わせることもできますが、スコアは予期したよりも高くなる場合があります。 例えば、3つの[!DNL Target] リクエストのそれぞれに10の値を割り当て、4番目のリクエストにスコアを割り当てずに、URL パラメーター`?mboxPageValue=5`を渡します。 値が割り当てられた3つのリクエストのページスコアは50:30、URL パラメーターのページスコアは20です（ページ上の4つのリクエストごとに5つ）。

また、費用がかかるページや訪問者が見る価値のないページには、負の値を割り当てることができます。 負の値も全体的なスコアに影響します。 この手法は、広告から訪問者がリーチするページで使用できるため、CPCの量を把握できます。 また、訪問者が電話をかけたり、支援をリクエストしたりするサポートページや問い合わせページでも使用できます。
